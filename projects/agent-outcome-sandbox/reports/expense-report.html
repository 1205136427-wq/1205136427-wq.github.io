Business Outcome Evaluation

Agent 业务结果评测沙箱

它把真实业务流程做成可执行、可回放、可判分的数字孪生：场景包定义数据、角色、状态与规则，Agent 只能通过 BusinessAPI 提交动作，再由确定性内核决定这个世界是否允许改变。

报销、采购、合同和短视频生成使用同一套机制。业务状态、权限、审批、产物规格和发布结果由状态机与轨迹判定；主观内容质量则交给人工评审或额外评估器，不伪装成确定性结论。

SAME ENGINE / DIFFERENT BUSINESSES
报销审批采购审批合同签署短视频生成与发布
ONE EVALUATION LOOP
01场景包数据 · 角色 · 状态 · 规则
02Agent 执行只能通过 BusinessAPI.act()
03确定性内核权限 → Guard → 迁移 → Effect
04轨迹与回放状态 · 违规 · 错误码 · 指纹
05攻击与证据红队 · 页面回放 · 双证据判分
06CI 门禁PASS / FAIL · 历史基线比较
SCENARIO DSL 业务可配置

每个业务由 flow.yaml、seed.json、expected.yaml 组成，声明状态、权限、硬规则、Effect、目标谓词和初始数据。

BUSINESS API 身份不可自报

演员身份在会话上下文中绑定。Agent 不能声称自己是经理，也没有直接写数据库的入口。

DETERMINISTIC KERNEL 失败即关闭

权限、Guard、状态迁移、Effect 和软规则依次执行；任一硬规则失败都不产生业务写入。

TRACE / REPLAY 结果可复算

完整轨迹记录演员、动作、入参、迁移、Effect、违规和耗时；快照与回放从同一初始世界复现结果。

RED TEAM / GUI 过程与页面一起验

红队验证越权、注入、幻觉和错误工具调用；视觉回归与联合判分防止页面正确掩盖后台错误。

RUNTIME 模型可替换

支持 DeepSeek、OpenAI 兼容接口与 LangGraph 适配器；可选 C++ 加速内核。判定不使用 LLM 裁判。

能力边界

状态机适合验证“是否按权限和流程办成”，不适合单独判断“视频是否好看”或“文案是否有创意”。视频画面、字幕、音频版权、审美与叙事质量需要人工量表、多模态模型或专用 artifact validator；异步生成任务还需 job adapter 把渲染开始、完成和失败转成可追踪业务事件。
